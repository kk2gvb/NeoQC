# NeoQC

**Быстрый и воспроизводимый контроль качества FASTQ-данных NGS.**

**Текущая версия:** `1.0.1`

NeoQC — инструмент первичного контроля качества данных секвенирования нового поколения (NGS). Он принимает FASTQ-данные, выполняет структурную проверку и расчёт набора метрик качества, формирует техническую оценку `PASS / WARNING / FAIL` и создаёт автономный HTML-отчёт.

Вычислительное ядро NeoQC реализовано на C++20 и использует OpenMP для параллельной обработки. Построение графиков и оценка QC выполняются Python-модулями.

## 1. Назначение

После секвенирования биологического материала результатом являются файлы FASTQ, содержащие последовательности прочтений и значения качества для каждого основания.

До последующего анализа необходимо проверить, что полученные данные не содержат очевидных технических проблем.

Упрощённо этот этап выглядит так:

```text
Секвенирование
      │
      ▼
    FASTQ
      │
      ▼
Контроль качества
      │
      ▼
Фильтрация / триммирование
      │
      ▼
Повторный контроль качества
      │
      ▼
Выравнивание / количественный анализ
      │
      ▼
Последующий анализ
```

NeoQC отвечает именно за этап **контроля качества FASTQ**. Он не выполняет trimming, alignment, variant calling или предсказание неоэпитопов.

Подробнее о FASTQ, paired-end секвенировании и месте QC в NGS-процессе:

[`docs/FastQ_origin_paired_end_and_plot_legends.md`](docs/FastQ_origin_paired_end_and_plot_legends.md)

## 2. Возможности

- FASTQ и `FASTQ.GZ`;
- single-end и paired-end библиотеки;
- проверка структуры FASTQ-записей;
- проверка согласованности R1/R2;
- параллельная обработка FASTQ через OpenMP;
- Phred-качество;
- качество по позициям;
- распределение среднего качества по прочтениям;
- GC-состав;
- состав A/C/G/T/N по позициям;
- содержание N;
- распределение длин прочтений;
- содержание адаптеров;
- точный расчёт дупликации 50-нуклеотидных префиксов;
- поиск overrepresented sequences;
- версионируемые правила технической оценки;
- статусы `PASS / WARNING / FAIL`;
- SVG и PNG-графики;
- автономный HTML-отчёт;
- пакетная обработка через `samples.csv`.

## 4. Быстрый запуск

### Single-end

```bash
./build/neoqc \
  --r1 sample.fastq.gz \
  --sample-id sample01 \
  --out results/sample01 \
  --plot
```

### Paired-end

```bash
./build/neoqc \
  --r1 sample_R1.fastq.gz \
  --r2 sample_R2.fastq.gz \
  --sample-id sample01 \
  --out results/sample01 \
  --plot
```

После выполнения при использовании `--plot` создаётся:

```text
results/sample01/neoqc_qc_report.html
```

Файл можно открыть непосредственно в браузере.

Подробное руководство:

**[`docs/USAGE.md`](docs/USAGE.md)**

## 5. Командная строка

| Параметр | Назначение |
|---|---|
| `--r1 <file>` | FASTQ-файл R1. |
| `--r2 <file>` | FASTQ-файл R2 для paired-end анализа. |
| `--sample-id <id>` | Идентификатор образца. |
| `--out <dir>` | Каталог результатов. |
| `--samples <csv>` | Проверка или пакетный анализ таблицы образцов. |
| `--plot` | Построение графиков, QC-оценки и HTML-отчёта. |
| `--skip-adapters` | Отключение поиска адаптеров. |
| `--timing` | Вывод времени выполнения этапов анализа. |
| `--help`, `-h` | Вывод справки. |

## 6. Пакетный анализ

Для нескольких образцов используется таблица `samples.csv`.

Пример:

[`examples/samples.csv`](examples/samples.csv)

Проверить таблицу:

```bash
./build/neoqc --samples examples/samples.csv
```

Запустить анализ:

```bash
./build/neoqc \
  --samples examples/samples.csv \
  --out results \
  --plot
```

Результаты организуются по схеме:

```text
<out>/
└── <patient_id>/
    └── <sample_id>/
        ├── результаты R1/R2
        ├── qc_evaluation.json
        └── neoqc_qc_report.html
```

Для случая также формируется машинно-читаемая сводка `case_summary.json`.

Формат таблицы и ограничения batch-режима описаны в [`docs/USAGE.md`](docs/USAGE.md).

## 7. Результаты анализа

Типичный каталог результата:

```text
results/sample01/
├── *_summary.txt
├── per_cycle_R*.tsv
├── per_sequence_quality_R*.tsv
├── per_base_sequence_content_R*.tsv
├── per_sequence_gc_content_R*.tsv
├── per_base_n_content_R*.tsv
├── sequence_length_distribution_R*.tsv
├── sequence_duplication_levels_R*.tsv
├── sequence_duplication_summary_R*.tsv
├── overrepresented_sequences_R*.tsv
├── adapter_content_R*.tsv
├── qc_evaluation.json
├── neoqc_qc_report.html
└── plots/
    ├── plots_manifest.json
    ├── *.svg        # графики на английском
    ├── *.ru.svg     # те же графики с русскими подписями
    └── *.png
```

### TSV

TSV-файлы содержат рассчитанные наблюдения отдельных метрик.

### `qc_evaluation.json`

Содержит машинно-читаемую техническую оценку, наблюдаемые значения, применённые пороги и информацию об активном ruleset.

### HTML-отчёт

HTML-отчёт объединяет итоговые QC-статусы, основную статистику, графики R1/R2, наблюдаемые значения с порогами и таблицы сверхпредставленных последовательностей.

- **автономный:** шрифты, графики (встроенный SVG), стили и скрипты находятся внутри одного файла — отчёт открывается без интернета и без NeoQC;
- **светлая и тёмная тема** — графики перекрашиваются вместе со страницей; печать и PDF всегда светлые;
- **английский и русский язык** — переключаются в левой панели без перегенерации, включая подписи на графиках;
- **порядок разделов:** «Приоритет» (сначала FAIL и WARNING, прошедшие модули свёрнуты в конце) или «По порядку»;
- работает на экранах от телефона до широкого монитора.

Подробное описание — [`docs/html-report.md`](docs/html-report.md).

## 8. Метрики

| Метрика | Что оценивается |
|---|---|
| Per-base sequence quality | Изменение качества оснований вдоль прочтения. |
| Per-sequence quality scores | Распределение среднего качества отдельных прочтений. |
| Per-base sequence content | Распределение A/C/G/T по позициям. |
| Per-sequence GC content | Распределение GC-содержания прочтений. |
| Per-base N content | Доля неопределённых оснований N по позициям. |
| Sequence length distribution | Распределение длин прочтений. |
| Sequence duplication | Доля дубликатов относительно определённого 50-nt ключа. |
| Adapter content | Содержание известных адаптерных последовательностей. |
| Overrepresented sequences | Последовательности, встречающиеся не менее чем в 0,1% прочтений. |

## 9. QC-статусы

| Статус | Значение |
|---|---|
| `PASS` | Значение соответствует заданным критериям. |
| `WARNING` | Значение пересекло предупреждающий порог. |
| `FAIL` | Значение пересекло порог отказа. |

Пороги задаются версионируемым ruleset.

Текущий профиль:

```text
fastqc-compatible-v1
```

Название означает совместимость семантики технических порогов с выбранным профилем FastQC; это не означает, что все внутренние алгоритмы NeoQC численно идентичны FastQC.

Подробнее:

[`docs/qc-status-engine.md`](docs/qc-status-engine.md)

## 10. Особенности расчёта

### Дупликация

NeoQC использует точный ключ из первых 50 нуклеотидов прочтения.

Каждый уникальный 50-nt префикс учитывается на протяжении всего входного файла. Ограничение по количеству наблюдаемых уникальных последовательностей не применяется.

Это обеспечивает точность для определённого ключа, но потребление памяти зависит от количества уникальных префиксов.

Подробнее:

[`docs/sequence-duplication.md`](docs/sequence-duplication.md)

### Адаптеры

Для поиска адаптеров используется отдельный версионируемый набор NeoQC:

```text
neoqc-standard-v1
```

Он является собственным набором NeoQC и не заявляется как буквальная копия внутреннего списка FastQC.

## 11. Производительность

Вычислительное ядро NeoQC использует OpenMP для параллельной обработки.

По измерениям проекта переход от реализации `v0.9.0` к `v1.0.0` сократил время выполнения контрольного набора примерно на **78%**.

Оптимизация вычислительного ядра не меняет определения рассчитываемых метрик.

Для просмотра времени выполнения:

```bash
./build/neoqc ... --timing
```

---

## 12. Ограничения

NeoQC является инструментом технического контроля качества FASTQ.

Он не выполняет:

- удаление адаптеров;
- quality trimming;
- фильтрацию reads;
- выравнивание на референс;
- variant calling;
- количественную оценку экспрессии;
- HLA typing;
- предсказание неоэпитопов.

Полученные QC-статусы требуют интерпретации с учётом типа библиотеки, протокола подготовки и последующего анализа.

## 13. Тестирование

После сборки рекомендуется выполнить:

```bash
ctest --test-dir build --output-on-failure
```

Тестовый набор включает проверки FASTQ-парсинга, ошибок структуры, Phred, N, GC, качества, дупликации, адаптеров, sample sheet, QC rules, графиков, HTML-отчёта и batch-обработки.

Тестовые FASTQ-данные генерируются средствами проекта.
