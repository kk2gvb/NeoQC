# NeoQC

## О проекте

**NeoQC** — внутренний программный модуль контроля качества данных секвенирования, разрабатываемый в рамках платформы проектирования персонализированных мРНК-вакцин.

Программа предназначена для проверки корректности файлов FASTQ, расчета статистик качества секвенирования, поиска адаптерных последовательностей и подготовки данных для последующих этапов биоинформатического анализа.

---


# Возможности

На данный момент реализованы следующие возможности:

- чтение файлов FASTQ;
- поддержка сжатых файлов (`.fastq.gz`);
- обработка single-end и paired-end данных;
- проверка структуры FASTQ;
- проверка синхронизации paired-end файлов;
- проверка идентификаторов paired-end чтений;
- вычисление статистики по ридам;
- анализ распределения длин последовательностей;
- расчет GC-содержания;
- расчет содержания символов `N`;
- анализ качества оснований;
- поиск адаптерных последовательностей;
- экспорт статистики;
- автоматическое построение графиков;
- автоматические тесты.

# Запуск программы

### Параметры командной строки

| Флаг | Обязательный | Описание |
|---|:---:|---|
| `--r1 <file>` | Да | Путь к FASTQ-файлу с прямыми чтениями (R1). Поддерживаются обычные и сжатые `.gz` файлы. |
| `--r2 <file>` | Нет | Путь к FASTQ-файлу с обратными чтениями (R2). Указывается только для парных чтений (*paired-end*). Если флаг не указан, данные обрабатываются как одиночные чтения (*single-end*). |
| `--sample-id <id>` | Да | Идентификатор анализируемого образца. Используется в именах создаваемых файлов результатов, например `sample01_R1_summary.txt`. |
| `--out <dir>` | Да | Папка для сохранения результатов анализа. Если папки ещё нет, NeoQC создаст её автоматически. |
| `--plot` | Нет | Запускает построение графиков по результатам анализа с помощью скрипта `scripts/plot_results.py`. Графики сохраняются в папке `<dir>/plots`. |
| `--skip-adapters` | Нет | Отключает поиск адаптеров для измерения производительности. Метрика и таблицы адаптеров в этом запуске не создаются. |
| `--timings` | Нет | Измеряет и выводит время основных этапов обработки. |
| `--help`, `-h` | Нет | Выводит краткую справку по использованию программы. |

# Одиночные чтения
``` bash
neoqc --r1 sample_R1.fastq.gz \
      --sample-id sample01 \
      --out results/sample01
```

# Парные чтения и построение графиков
``` bash
neoqc --r1 sample_R1.fastq.gz \
      --r2 sample_R2.fastq.gz \
      --sample-id sample01 \
      --out results/sample01 \
      --plot
```

### Измерение без поиска адаптеров

```bash
neoqc --r1 sample_R1.fastq.gz \
      --sample-id sample01 \
      --out results/sample01_without_adapters \
      --skip-adapters
```

Этот режим предназначен для сравнения производительности. В summary будет указано, что
доля чтений с адаптером не вычислялась; файлы `adapter_content_*.tsv` и графики адаптеров
не создаются.

С флагом `--timings` NeoQC выводит измеренное время открытия файлов, чтения и
распаковки, проверки структуры FASTQ, проверки пар, расчёта метрик, поиска адаптеров,
записи отчётов и построения графиков. В single-end режиме время проверки пар равно нулю;
при `--skip-adapters` время поиска адаптеров также равно нулю.

# Описание случая и образцов

Для запуска QC всех библиотек одного пациента используется CSV-таблица. Пример находится
в [examples/samples.csv](examples/samples.csv). В ней одна строка описывает один образец:

| Столбец | Назначение |
|---|---|
| `patient_id` | Обезличенный идентификатор пациента или исследуемого случая. |
| `sample_id` | Уникальное имя образца в пределах случая. |
| `sample_role` | Роль: `tumor`, `normal` или `tumor_rna`. |
| `material` | Материал: `dna` или `rna`. |
| `r1` | Путь к R1 FASTQ. |
| `r2` | Путь к R2 FASTQ; для single-end данных оставляется пустым. |
| `platform` | Платформа секвенирования, например `illumina`. |
| `library_type` | Вид библиотеки, например `wes`, `wgs`, `rna_seq` или `panel`. |
| `reference` | Версия референсного генома, например `GRCh38`. |

Пути в примере заданы относительно корня проекта. На следующем шаге NeoQC получит режим
чтения и проверки этой таблицы до запуска анализа FASTQ.

Проверить только таблицу:

```bash
./build/neoqc --samples examples/samples.csv
```

Запустить QC для всех образцов таблицы:

```bash
./build/neoqc --samples examples/samples.csv --out results
```

Результаты каждого образца сохраняются в `<out>/<patient_id>/<sample_id>/`. Если хотя бы
один образец не проходит QC, NeoQC завершится с ошибкой после обработки всех доступных
образцов.

Для каждого пациента также создаётся `<out>/<patient_id>/case_summary.json`. В нём
содержатся идентификатор пациента, итоговый статус случая, версия NeoQC, дата запуска,
предупреждения и для каждого образца его роль, материал, пути FASTQ, QC-статус и число
прочтений R1/R2.

# Проверка FASTQ

Во время обработки NeoQC выполняет следующие проверки:

- корректность структуры FASTQ;
- наличие всех четырех строк записи;
- совпадение длины последовательности и строки качества;
- корректность заголовка (`@`);
- корректность строки-разделителя (`+`);
- отсутствие поврежденных записей;
- совпадение количества чтений в paired-end файлах;
- совпадение идентификаторов paired-end чтений.

При обнаружении ошибки программа завершает работу с сообщением, содержащим описание причины ошибки.

Создаются следующие файлы:

- summary.txt
- per_cycle_R1.tsv
- per_cycle_R2.tsv

- per_sequence_quality_R2.tsv

- quality_distribution
- plots

# Построение графиков

Основной анализ данных выполняется модулем **NeoQC**, написанным на языке **C++**.

Для визуализации результатов используются Python-скрипты, автоматически строящие графики по рассчитанным статистикам.

В дальнейшем планируется автоматическая генерация HTML- и PDF-отчетов для передачи результатов в лабораторию.

---

# Тестирование

Для проверки корректности работы используется набор автоматических тестов.

Запуск тестов:

```bash
cd build
ctest -V -O ../ctest.log
```

Тесты покрывают:

- корректные FASTQ-файлы;
- поврежденные FASTQ-файлы;
- single-end обработку;
- paired-end обработку;
- работу со сжатыми файлами;
- обработку длинных строк;
- различные варианты окончания строк;
- проверку идентификаторов paired-end чтений.
