# HTML-отчёт NeoQC

Документ описывает автономный HTML-отчёт `neoqc_qc_report.html`: его интерфейс,
режимы работы, контракт входных данных, устройство кода, правила доработки и
тестирование.

## 1. Назначение

HTML-отчёт — представление результатов NeoQC для человека. Он объединяет
технические статусы `PASS / WARNING / FAIL / NOT EVALUATED`, основную
статистику, графики по R1 и R2, наблюдаемые значения, применённые пороги и
таблицы сверхпредставленных последовательностей.

Для машинной обработки используются `qc_evaluation.json` и
`plots/plots_manifest.json`; отчёт только отображает их и ничего не вычисляет.

Отчёт создаётся при запуске с `--plot`:

```bash
./build/neoqc \
  --r1 sample_R1.fastq.gz \
  --r2 sample_R2.fastq.gz \
  --sample-id sample01 \
  --out results/sample01 \
  --plot
```

Результат — `results/sample01/neoqc_qc_report.html`.

Пересобрать только отчёт из уже готовых TSV, графиков и `qc_evaluation.json`:

```bash
python3 scripts/generate_qc_report.py results/sample01
python3 scripts/generate_qc_report.py results/sample01 --output /tmp/sample01.html
```

## 2. Автономность

Отчёт — один HTML-файл без внешних зависимостей. Внутрь встроены:

- шрифты IBM Plex Sans и IBM Plex Mono (`woff2`, латиница и кириллица);
- графики в виде встроенного SVG — отдельно для английского и русского языков;
- стили и скрипты.

Файл открывается в любом современном браузере без интернета, без установки
NeoQC и без доступа к каталогу результатов. Размер для paired-end библиотеки —
около 1,4 МБ: 32 SVG-графика (16 × 2 языка) ≈ 1,0 МБ, шрифты ≈ 0,3 МБ,
разметка, стили и скрипты ≈ 60 КБ.

## 3. Интерфейс

```text
┌ Верхняя панель ─────────────────────────────────────────────────────────────┐
│ NeoQC Report │ Образец │ Риды │ Создан │ Набор правил │ Порядок │ Свернуть │ Печать │
├ Левая панель ─────┬ Основная область ──────────────────────────────────────┤
│ Тема   ☀ | ☾       │ Обзор QC: образец, факты, пояснение, счётчики, матрица │
│ Язык   EN | RU     │ Основная статистика (INFO)                             │
│ Разделы отчёта     │ ── Требует внимания ──                                 │
│  00 Обзор QC       │ Модуль: R1 | R2 (график, наблюдения, причина)         │
│  01 Основная стат. │ ── Пройдено · свёрнуто ──                              │
│  NN модуль  [R1][R2]│ Модуль ▸ R1 26 Phred · R2 23 Phred         [PASS]      │
│ Легенда статусов   │                                                        │
└────────────────────┴────────────────────────────────────────────────────────┘
```

**Верхняя панель** закреплена при прокрутке. Слева — идентификатор образца,
набор ридов, дата создания и набор правил; справа — переключатель порядка
разделов, кнопка «Свернуть всё / Развернуть всё» и печать.

**Левая панель** содержит переключатели темы и языка, список разделов и
легенду. У каждого модуля в списке — ячейки статусов R1 и R2. Раздел, который
сейчас находится вверху экрана, подсвечивается. Щелчок по разделу прокручивает
к нему и раскрывает его, если он был свёрнут.

**Обзор QC** — первый раздел: идентификатор образца, наборы ридов, число
построенных графиков, число ошибок построения, пояснение о природе статусов,
итоговый статус, счётчики по статусам, пропорциональная полоса и матрица
«модуль × рид».

**Основная статистика** (`INFO`) всегда идёт сразу после обзора, в любом
режиме порядка.

**Модуль** — панель с заголовком, агрегированным статусом и двумя дорожками
R1/R2. В дорожке: собственный статус рида, график (щелчок открывает его в
увеличенном окне), наблюдаемые значения, причина статуса и — для дупликации —
таблица сверхпредставленных последовательностей.

## 4. Порядок разделов

Переключатель «Порядок» в верхней панели.

| Режим | Как упорядочены модули | Что свёрнуто |
|---|---|---|
| **Приоритет** (`Triage`, по умолчанию) | Обзор QC → Основная статистика → «Требует внимания»: сначала `FAIL`, затем `WARNING`, затем `NOT EVALUATED` → «Пройдено»: модули `PASS` | модули `PASS` |
| **По порядку** (`Sequential`) | Обзор QC → Основная статистика → модули в порядке конвейера NeoQC | ничего |

Внутри группы сохраняется порядок конвейера. `NOT EVALUATED` попадает в
«Требует внимания»: отсутствие оценки не является прохождением проверки и
требует разбора. Одновременно перестраиваются основная область, список в
левой панели и строки матрицы в обзоре. В режиме «Приоритет» у проблемных
панелей появляется цветная полоса слева.

Статус модуля — худший из статусов его ридов (`FAIL` > `WARNING` > `PASS`;
`NOT EVALUATED` учитывается, только если оценённых ридов нет).

## 5. Сворачивание

- Любую панель, кроме обзора, можно свернуть щелчком по заголовку или по
  кнопке-шеврону.
- Свёрнутая панель показывает первое наблюдение по каждому риду, например
  «R1 26 Phred · R2 23 Phred».
- «Свернуть всё / Развернуть всё» действует на все панели.
- Смена режима порядка заново применяет правила сворачивания из таблицы выше.
- Переход по ссылке из левой панели или по якорю в адресе (`#module-…`)
  раскрывает целевой раздел.

## 6. Тема оформления

Переключатель «Тема» (☀ / ☾) в левой панели.

- При первом открытии тема берётся из настроек системы
  (`prefers-color-scheme`), дальше — из сохранённого выбора.
- Тема применяется скриптом в `<head>` до первой отрисовки, поэтому страница не
  «мигает» светлой темой.
- Графики следуют теме. При встраивании SVG каждый цвет Matplotlib заменяется
  CSS-переменной `var(--c-…)`; значения для светлой и тёмной темы заданы в
  `scripts/neoqc_theme.py`.
- **Печать и PDF всегда в светлой теме**, независимо от выбора на экране.

## 7. Язык

Переключатель «Язык» (EN / RU) в левой панели. При первом открытии язык
берётся из языка браузера (`ru*` → русский, иначе английский).

Отчёт содержит оба языка сразу: переводимый текст записан парой
`<span class="l-en">…</span><span class="l-ru">…</span>`, CSS показывает ту,
что соответствует `<html lang>`. Перегенерация отчёта для смены языка не нужна.

**Переводится:** интерфейс, названия модулей, строки основной статистики,
названия наблюдений, стандартные сообщения о причинах статусов (включая
значения и пороги, например «Макс. доля адаптеров: 11.95 %; порог FAIL > 10 %.»),
подписи на графиках — оси, легенды и аннотации.

**Не переводится намеренно:**

- статусы `PASS / WARNING / FAIL / NOT EVALUATED / INFO` — общепринятые в QC
  обозначения (как в FastQC);
- названия адаптеров (`TruSeq_R1`, `Nextera`, `PolyG` …), идентификатор образца,
  имя набора правил, числа;
- сообщения пользовательских наборов правил, которых нет в словаре, — они
  показываются по-английски в обоих режимах.

Русские графики — отдельные файлы `<график>_<рид>.ru.svg`, которые
`plot_metrics.py` создаёт из той же фигуры после сохранения английской версии.
Если русского файла нет (старые результаты или сбой перевода), в обоих языках
показывается английский график.

## 8. Сохранённые настройки

Выбор хранится в `localStorage` браузера и общий для всех отчётов NeoQC,
открытых из одного места:

| Ключ | Значения |
|---|---|
| `neoqc.report.theme` | `light`, `dark` |
| `neoqc.report.lang` | `en`, `ru` |
| `neoqc.report.order` | `triage`, `sequential` |

Если хранилище недоступно (приватный режим, запрет сайта), отчёт работает с
настройками по умолчанию, просто не запоминает их. Без JavaScript отчёт
показывается полностью развёрнутым, в порядке конвейера, на английском и в
светлой теме.

## 9. Печать и PDF

Кнопка «Печать / PDF» или `Ctrl+P`. При печати:

- включается светлая тема;
- все свёрнутые разделы раскрываются, после печати состояние восстанавливается;
- скрываются верхняя и левая панели;
- дата создания печатается в блоке обзора;
- панели по возможности не разрываются между страницами.

## 10. Адаптивность

| Ширина окна | Раскладка |
|---|---|
| ≥ 1000 px | левая панель слева, R1 и R2 рядом |
| < 1000 px | левая панель над содержимым, список разделов свёрнут под заголовком «Разделы отчёта ▾»; кнопка печати скрыта (доступна `Ctrl+P`) |
| < 700 px | R1 и R2 друг под другом, верхняя панель переносится на две строки |

На телефоне графики мелкие; щелчок открывает окно, где график показывается
шириной не менее 720 px с горизонтальной прокруткой.

## 11. Доступность

- Статус никогда не передаётся только цветом: у плашек и ячеек есть символ
  (✓ ▲ ✕ —) и текст или подсказка.
- Контраст текста на плашках статусов и мелких подписей — не ниже 4,5:1
  (WCAG AA) в обеих темах. На `WARNING` используется тёмный текст.
- Переключатели имеют `aria-pressed`, кнопки сворачивания — `aria-expanded`,
  графики — `role="img"` и `aria-label` с текстовым описанием из манифеста.
- Видимая рамка фокуса для клавиатуры (`:focus-visible`), учёт
  `prefers-reduced-motion`.

## 12. Безопасность

Отчёт может открываться вне доверенной среды, поэтому:

- все значения из TSV, JSON и сводок экранируются;
- пути к графикам из манифеста не могут выйти за каталог `plots/`;
- SVG перед встраиванием разбирается как XML и очищается: остаются только
  элементы, которые создаёт Matplotlib (`svg`, `g`, `path`, `text`, `use`,
  `clipPath` …); удаляются `script`, `foreignObject`, `image`, `style`,
  атрибуты `on*`, внешние ссылки и `url(…)` на внешние ресурсы; файлы с
  `<!ENTITY>` или внутренним DTD отклоняются;
- идентификаторы внутри каждого SVG получают уникальный префикс
  (`<модуль>-<рид>-<язык>-`), поэтому графики не мешают друг другу;
- отчёт не загружает внешних ресурсов.

Если график не прошёл проверку, вместо него показывается сообщение
«Файл графика недоступен: …»; QC-статус при этом не меняется.

## 13. Входные данные

Генератор читает каталог результатов образца:

| Файл | Обязателен | Использование |
|---|---|---|
| `plots/plots_manifest.json` | да | список графиков, статусы построения, пути к SVG/PNG, `alt_text`, русские варианты (`localized`) |
| `qc_evaluation.json` | нет | QC-статусы, наблюдения, причины, набор правил |
| `<образец>_R1_summary.txt`, `…_R2_summary.txt` | нет | основная статистика |
| `overrepresented_sequences_R1.tsv`, `…_R2.tsv` | нет | таблицы под графиком дупликации |

Фрагмент записи манифеста:

```json
{
  "id": "adapter_content",
  "read": "R1",
  "title": "Adapter content",
  "status": "generated",
  "svg": "adapter_content_R1.svg",
  "png": "adapter_content_R1.png",
  "localized": {"ru": {"svg": "adapter_content_R1.ru.svg"}},
  "alt_text": "Adapter content by position for R1; maximum 11.95%."
}
```

Полный контракт манифеста описан в [`plots.md`](plots.md), контракт статусов —
в [`qc-status-engine.md`](qc-status-engine.md).

**Обратная совместимость:**

- манифест без `localized` — английские графики в обоих языках;
- запуск `--formats png` — графики встраиваются как PNG и не перекрашиваются в
  тёмной теме;
- нет `qc_evaluation.json` — все модули `NOT EVALUATED`, выведенный PASS не
  подставляется;
- ошибка построения графика отображается как состояние артефакта (`ERROR`,
  `NOT RUN`) и никогда не превращается в биологический `FAIL`.

## 14. Устройство кода

| Файл | Роль |
|---|---|
| `scripts/qc_report.py` | модель отчёта (`load_report_model`), очистка и встраивание SVG, разметка, CSS, JavaScript, `generate_qc_report` |
| `scripts/generate_qc_report.py` | CLI для пересборки отчёта |
| `scripts/plot_results.py` | CLI: графики → `qc_evaluation.json` → отчёт; вызывается из `neoqc --plot` |
| `scripts/plot_metrics.py` | построение графиков, русские SVG, манифест |
| `scripts/plot_style.py` | единый стиль графиков: шрифты, размеры, сетка, палитра |
| `scripts/neoqc_theme.py` | цветовые токены графиков для светлой и тёмной темы (без Matplotlib) |
| `scripts/neoqc_i18n.py` | словари перевода интерфейса (`UI`) и графиков (`CHART`, `CHART_PATTERNS`) |
| `assets/fonts/ibm-plex/` | шрифты IBM Plex (TTF для Matplotlib, `woff2` для отчёта), лицензия OFL |

Порядок разделов реализован без перегенерации: у каждого раздела, пункта
навигации и строки матрицы есть атрибуты `data-seq` (порядок конвейера) и
`data-tri` (приоритет); скрипт сортирует элементы по нужному ключу.

## 15. Как дорабатывать

**Изменить цвета интерфейса.** Переменные светлой и тёмной темы — `_LIGHT_VARS`
и `_DARK_VARS` в `qc_report.py`. После изменения проверьте контраст текста на
плашках (≥ 4,5:1).

**Изменить цвета графиков.** Только через `CHART_COLORS` в `neoqc_theme.py`.
Светлые значения должны быть уникальны: по ним отчёт находит цвет в SVG и
подставляет переменную. Графики должны использовать только константы из
`plot_style.py`; тест `test_russian_chart_variants_and_theme_palette` падает,
если в SVG появился цвет вне палитры (такой цвет не перекрасится в тёмной теме).

**Добавить или изменить перевод.** Строку интерфейса — в `UI`, подпись графика —
в `CHART`, подпись с числами — регулярным выражением в `CHART_PATTERNS`
(`neoqc_i18n.py`). Исходный язык всех строк — английский; в коде отчёта и
графиков пишется английская строка, перевод берётся из словаря. Сообщения о
причинах статусов формата `<название>: <значение>; <УРОВЕНЬ> threshold <оп> <порог>.`
переводятся автоматически, если название есть в `UI`.

**Добавить модуль QC.** Добавьте перевод его заголовка и наблюдений в `UI`,
подписи осей и легенд — в `CHART`.

**Добавить язык.** Нужны: словари для нового языка в `neoqc_i18n.py`, переводчик
в `_CHART_TRANSLATORS` (`plot_metrics.py`), код языка в `SUPPORTED_LOCALES`
(`qc_report.py`), функция двуязычного текста `_t` и кнопка в `prefs`, правило
CSS видимости `.l-<код>`.

## 16. Тестирование

Автоматические тесты запускаются вместе с остальными:

```bash
ctest --test-dir build --output-on-failure
python3 tests/test_qc_report.py
python3 tests/test_plot_results.py
```

`tests/test_qc_report.py` проверяет:

- автономность: встроенные SVG вместо ссылок, отсутствие внешних ресурсов,
  14 `@font-face` (7 начертаний × латиница/кириллица);
- очистку SVG: удаление `script`, `on*`, `foreignObject`, `style`, внешних
  ссылок; отказ для `<!ENTITY>`; префиксы идентификаторов; замену цветов на
  CSS-переменные, в том числе в атрибутах `fill`;
- русские варианты графиков и возврат к английскому при их отсутствии;
- наличие переключателей темы, языка и порядка, раннее применение темы в
  `<head>`, светлую палитру для печати;
- ключи сортировки: обзор и основная статистика первыми, проблемы раньше
  прошедших модулей, прошедшие модули сворачиваются;
- экранирование значений, матрицу статусов, причины, таблицы сверхпредставленных
  последовательностей, запрет выхода пути за каталог графиков;
- перевод сообщений с числами и подписей графиков;
- синтаксис встроенного JavaScript через `node --check` (тест пропускается, если
  Node.js не установлен).

`tests/test_plot_results.py` дополнительно проверяет, что для каждого графика
создан русский SVG, что все цвета в SVG принадлежат палитре, что текст остаётся
текстом с запасным шрифтом и что запуск только с PNG не создаёт русских SVG.

**Ручная проверка в браузере** перед выпуском изменений дизайна:

1. Открыть отчёт в Chrome/Edge и Firefox на ширине 1440, 1000, 700 и 390 px —
   нет горизонтальной прокрутки страницы.
2. Переключить тему и язык, перезагрузить страницу — выбор сохранился; графики
   перекрашены и подписаны на выбранном языке.
3. Переключить «Приоритет / По порядку», свернуть и развернуть разделы,
   перейти к свёрнутому разделу из левой панели.
4. Открыть график в увеличенном окне и закрыть его (кнопка, щелчок по фону, `Esc`).
5. Напечатать в PDF из тёмной темы — PDF светлый, все разделы раскрыты, дата
   создания есть.

## 17. Ограничения

- Отчёт рассчитан на один образец; сводка по случаю — `case_summary.json`.
- Разделители разрядов в таблицах — запятые (`19,564`) в обоих языках.
- Графики на экранах уже 400 px читаются только в увеличенном окне.
- Настройки темы, языка и порядка общие для всех отчётов, открытых с одного
  адреса (`file://` или сервера).
- Автоматической проверки в настоящем браузере (скриншоты, печать) в `ctest`
  нет; её заменяет ручной чек-лист выше.
