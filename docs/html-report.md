# Python-модуль HTML-отчёта

Модуль отделяет расчёты пайплайна от представления клинического документа. Он работает
на Python 3.10+ и использует только стандартную библиотеку. Существующий C++-код NeoQC
не изменён и не зависит от модуля отчёта.

## Генерация из JSON

Самая слабосвязанная граница интеграции — JSON. Пример входного файла находится в
`examples/html_report_example.json`:

```bash
python3 scripts/generate_html_report.py \
  --input examples/html_report_example.json \
  --output results/report.html
```

Скрипт проверяет обязательные поля, статусы и размеры таблиц. При ошибке он ничего не
публикует по целевому пути и завершается с ненулевым кодом.

## Использование как Python API

Если аналитический код также написан на Python, данные можно передать без промежуточного
файла:

```python
from neoqc_report import ReportData, write_html_report

report = ReportData.from_dict(calculated_report_data)
write_html_report(report, "results/report.html")
```

При локальном запуске каталог `python` должен находиться в `PYTHONPATH`:

```bash
PYTHONPATH=python python3 -m neoqc_report \
  --input examples/html_report_example.json \
  --output results/report.html
```

## Контракт данных

- `ReportData` — шапка документа, метаданные, разделы и итоговые выводы.
- `Section` — смысловой раздел с кратким текстом, метриками и таблицами.
- `Metric` — подпись, значение, единица измерения, референс и статус.
- Допустимые статусы: `not_evaluated`, `passed`, `warning`, `failed`.
- Значения метрик могут приходить из JSON числами, но внутри отчёта всегда становятся
  текстом без неявного округления.

Все внешние значения экранируются. HTML-теги из аналитического кода не исполняются.
Файл записывается через временный файл и атомарную замену, чтобы клиника не получила
частично сформированный документ.

Автоматическое создание отчёта из `case_summary.json` пока намеренно не включено:
сначала следует согласовать клинические разделы, пороги, формулировки и обязательные поля.
