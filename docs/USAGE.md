# Использование NeoQC

NeoQC выполняет технический контроль качества FASTQ-данных. При запуске с `--trim` программа также обрабатывает прочтения, сохраняет очищенные FASTQ и рассчитывает QC **до и после** тримминга.

Поддерживаются обычные и сжатые (`.gz`) FASTQ-файлы, single-end и paired-end режимы. Графики, оценка по правилам и HTML-отчёты создаются при использовании `--plot`.

## 1. Общая схема

### Только контроль качества (по умолчанию)

```text
FASTQ / FASTQ.GZ
       │
       ▼
Проверка структуры FASTQ и согласованности R1/R2
       │
       ▼
Расчёт метрик качества
       ├── Phred-качество по позициям и прочтениям
       ├── GC, A/C/G/T/N, распределение длин
       ├── дупликация, overrepresented sequences
       └── содержание адаптеров
       │
       ▼
TSV-артефакты и сводки
       │
       └── при --plot: QC evaluation → графики → HTML-отчёт
```

### Контроль качества и тримминг (`--trim`)

```text
Исходные FASTQ
       │
       ├───────────────────────┐
       ▼                       ▼
 QC до обработки         Тримминг / фильтрация
   qc/before/                   │
                                ▼
                       Очищенные FASTQ.GZ
                                │
                                ▼
                          QC после обработки
                             qc/after/
                                │
       ┌────────────────────────┘
       ▼
Статистика trimming_report.json
       │
       └── при --plot: графики, QC-статусы и HTML-отчёты до/после
```

Без `--trim` исходные прочтения не изменяются. С `--trim` NeoQC записывает обработанные FASTQ в новый каталог результатов. Конкретные операции обрезки задаются отдельными параметрами.

## 2. Single-end

Минимальный запуск, без построения графиков:

```bash
./build/neoqc \
  --r1 sample.fastq.gz \
  --sample-id sample01 \
  --out results/sample01
```

С построением графиков, оценкой качества и HTML-отчётом:

```bash
./build/neoqc \
  --r1 sample.fastq.gz \
  --sample-id sample01 \
  --out results/sample01 \
  --plot
```

При `--plot` отчёт располагается в `results/sample01/neoqc_qc_report.html`.

## 3. Paired-end

```bash
./build/neoqc \
  --r1 sample_R1.fastq.gz \
  --r2 sample_R2.fastq.gz \
  --sample-id sample01 \
  --out results/sample01 \
  --plot
```

NeoQC проверяет согласованность парных прочтений, а QC-метрики рассчитываются и отображаются отдельно для R1 и R2.

## 4. Параметры командной строки

### Основные параметры

| Параметр | Назначение |
|---|---|
| `--r1 <file>` | Входной FASTQ-файл R1 (или single-end). |
| `--r2 <file>` | Входной FASTQ-файл R2 для paired-end. |
| `--sample-id <id>` | Идентификатор образца. |
| `--out <dir>` | Каталог результатов; при использовании `--samples` включает batch-обработку. |
| `--samples <csv>` | Проверка таблицы образцов; вместе с `--out` — запуск batch-анализа. |
| `--plot` | Генерация графиков, `qc_evaluation.json` и HTML-отчёта. |
| `--trim` | Включение пайплайна тримминга, записи обработанных FASTQ и QC до/после. |
| `--full-trim` | Стандартный профиль тримминга: адаптеры NeoQC, обрезка по качеству, polyG/polyX и минимальная длина `50` п.н. |
| `--skip-adapters` | Отключение **QC-анализа** содержания адаптеров; не является параметром удаления адаптеров при тримминге. |
| `--help`, `-h` | Справка по CLI. |

Проверить доступные опции:

```bash
./build/neoqc --help
```

### Параметры тримминга

Все перечисленные ниже параметры применяются вместе с `--trim`.

`--full-trim` уже включает `--trim` и настраивает следующие значения:

- адаптеры из `config/adapters/neoqc-standard-v1.tsv`;
- `--cut-front`, `--cut-tail`, `--cut-right`;
- `--quality-threshold 20`, `--window-size 4`;
- `--trim-polyg`, `--trim-polyx` с минимальной длиной `10` п.н.;
- `--min-length 50`.

Коррекция перекрытий, объединение пар и UMI в профиль не входят: первые две
операции применимы только к paired-end библиотекам, а для UMI требуется
известная длина. Их следует задавать явно. Параметры, указанные после
`--full-trim`, переопределяют соответствующие значения профиля.

| Параметр | Назначение |
|---|---|
| `--trim-front N` | Фиксированное удаление `N` оснований с 5′-конца. |
| `--trim-tail N` | Фиксированное удаление `N` оснований с 3′-конца. |
| `--cut-front` | Удаление низкокачественных оснований с 5′-конца. |
| `--cut-tail` | Удаление низкокачественных оснований с 3′-конца. |
| `--cut-right` | Обрезка по первому низкокачественному скользящему окну. |
| `--quality-threshold N` | Порог качества Phred, по умолчанию `20`. |
| `--window-size N` | Размер скользящего окна, по умолчанию `4`. |
| `--adapter-sequence SEQ` | Удаление указанной адаптерной последовательности. |
| `--adapter-config FILE` | Загрузка адаптеров для тримминга из TSV-файла. |
| `--min-length N` | Отбрасывание прочтений короче `N` оснований после обработки; по умолчанию `0`. |
| `--trim-polyg` | Удаление терминального участка polyG. |
| `--polyg-min-length N` | Минимальная длина polyG-участка; по умолчанию `10`. |
| `--trim-polyx` | Удаление терминальных гомополимерных A/C/G/T-участков. |
| `--polyx-min-length N` | Минимальная длина polyX-участка; по умолчанию `10`. |
| `--overlap-correction` | Коррекция несовпадений R1/R2 в найденном перекрытии с учётом качества оснований. |
| `--merge` | Дополнительная запись консенсусных reads для перекрывающихся пар. |
| `--umi` | Извлечение UMI с 5′-конца R1 (либо единственного read в single-end режиме). |
| `--umi-length N` | Длина извлекаемого UMI; требуется вместе с `--umi`. |

Ограничения и особенности:

- `--overlap-correction` и `--merge` требуют paired-end входных файлов (`--r1` и `--r2`).
- `--umi` требует `--umi-length` больше нуля. Извлечённый UMI сохраняется в заголовке read; соответствующие основания и символы качества удаляются из начала read.
- Для удаления адаптеров при тримминге следует явно указать `--adapter-sequence` и/или `--adapter-config`. Сам по себе `--trim` не означает автоматическую загрузку списка адаптеров для их удаления.
- `--skip-adapters` относится к расчёту QC-метрики `Adapter content`. Он не заменяет настройку `--adapter-config` для тримминга.
- В paired-end режиме, если хотя бы один read пары не проходит фильтрацию, пара не записывается в обработанные R1/R2 FASTQ.
- `--merge` создаёт **дополнительный** файл `merged.fastq.gz` для пар с подходящим перекрытием; R1/R2 выходные файлы при этом также сохраняются.
- Для запуска с `--trim` входные FASTQ не должны находиться внутри каталога `--out`: NeoQC проверяет это, чтобы избежать повреждения входных данных.

## 5. Примеры тримминга

### 5.1. Single-end: обрезка по качеству и длине

```bash
./build/neoqc \
  --r1 sample.fastq.gz \
  --sample-id sample01 \
  --out results/sample01_trimmed \
  --trim \
  --cut-front --cut-tail \
  --quality-threshold 20 \
  --min-length 50 \
  --plot
```

Будут сформированы `trimmed/R1.trimmed.fastq.gz`, QC до/после и HTML-отчёты.

### 5.2. Paired-end: адаптеры, качество, polyG/polyX

Запуск из корня репозитория:

```bash
./build/neoqc \
  --r1 sample_R1.fastq.gz \
  --r2 sample_R2.fastq.gz \
  --sample-id sample01 \
  --out results/sample01_trimmed \
  --full-trim \
  --plot
```

Параметры обрезки комбинируются; для конкретного типа библиотеки необходимо подобрать их по результатам исходного QC. Использование сразу всех способов обрезки не является обязательным.

### 5.3. Дополнительная обработка перекрытий и UMI

Опциональные параметры для paired-end запуска:

```bash
--overlap-correction --merge --umi --umi-length 8
```

Здесь `--overlap-correction` корректирует несовпадения в области перекрытия, `--merge` создаёт дополнительный файл консенсусных reads, а `--umi` извлекает первые 8 оснований R1 как UMI. Эти параметры следует добавлять к полной команде с `--trim`, `--r1`, `--r2`, `--sample-id` и `--out`.

## 6. Batch-анализ

Формат таблицы образцов:

```text
patient_id,sample_id,sample_role,material,r1,r2,platform,library_type,reference
```

Пример находится в [`../examples/samples.csv`](../examples/samples.csv).

Проверить CSV без анализа FASTQ:

```bash
./build/neoqc --samples examples/samples.csv
```

Запустить batch QC:

```bash
./build/neoqc \
  --samples examples/samples.csv \
  --out results \
  --plot
```

Запустить batch с триммингом:

```bash
./build/neoqc \
  --samples examples/samples.csv \
  --out results_trimmed \
  --trim \
  --cut-tail --quality-threshold 20 \
  --min-length 50 \
  --plot
```

Каталог каждого образца создаётся по схеме `<out>/<patient_id>/<sample_id>/`. В каталоге пациента создаётся `case_summary.json` со сведениями о выполнении анализа образцов. При `--trim` каждый образец получает структуру результатов до/после обработки, описанную ниже.

## 7. Выходные данные

### 7.1. Обычный QC

Пример состава каталога **при использовании `--plot`**:

```text
results/sample01/
├── run_manifest.json
├── <sample_id>_R1_summary.txt
├── <sample_id>_R2_summary.txt             # только paired-end
├── per_cycle_R*.tsv
├── per_sequence_quality_R*.tsv
├── per_base_sequence_content_R*.tsv
├── per_sequence_gc_content_R*.tsv
├── per_base_n_content_R*.tsv
├── sequence_length_distribution_R*.tsv
├── sequence_duplication_levels_R*.tsv
├── sequence_duplication_summary_R*.tsv
├── overrepresented_sequences_R*.tsv
├── adapter_content_R*.tsv                  # если анализ адаптеров не отключён
├── qc_evaluation.json                      # при --plot
├── neoqc_qc_report.html                    # при --plot
└── plots/                                  # при --plot
    ├── plots_manifest.json
    ├── *.svg
    ├── *.ru.svg
    └── *.png
```

Без `--plot` NeoQC сохраняет рассчитанные TSV, сводки и `run_manifest.json`, но не создаёт графики, `qc_evaluation.json` и HTML-отчёт.

### 7.2. QC с триммингом

Пример структуры для paired-end запуска с `--trim --plot`:

```text
results/sample01_trimmed/
├── run_manifest.json
├── trimming_report.json
├── trimmed/
│   ├── R1.trimmed.fastq.gz
│   ├── R2.trimmed.fastq.gz
│   └── merged.fastq.gz                    # только при --merge
├── qc/
│   ├── before/
│   │   ├── <sample_id>_R1_summary.txt
│   │   ├── <sample_id>_R2_summary.txt
│   │   ├── *.tsv
│   │   ├── qc_evaluation.json              # при --plot
│   │   └── neoqc_qc_report.html           # при --plot
│   └── after/
│       ├── <sample_id>_R1_summary.txt
│       ├── <sample_id>_R2_summary.txt
│       ├── *.tsv
│       ├── qc_evaluation.json              # при --plot
│       └── neoqc_qc_report.html           # при --plot
├── plots/                                  # при --plot
│   ├── before/
│   │   ├── plots_manifest.json
│   │   └── *.svg, *.ru.svg, *.png
│   └── after/
│       ├── plots_manifest.json
│       └── *.svg, *.ru.svg, *.png
└── neoqc_trimming_report.html              # при --plot
```

В single-end режиме `R2.trimmed.fastq.gz` и относящиеся к R2 артефакты отсутствуют.

`trimming_report.json` содержит числовую статистику: количество входных, сохранённых и отброшенных reads, число оснований до/после обработки, количество reads с применёнными операциями тримминга, сведения об UMI, коррекции перекрытий и объединённых парах.

`neoqc_trimming_report.html` сопоставляет основную статистику, статусы и графики QC до/после, а также показывает параметры и итоги тримминга. Этот файл можно открыть без интернета.

### 7.3. Назначение основных файлов

| Файл | Назначение |
|---|---|
| `run_manifest.json` | Идентификатор запуска, входы, параметры и опубликованные артефакты. |
| `*.tsv` | Числовые результаты расчёта QC-метрик. |
| `qc_evaluation.json` | Машинно-читаемые QC-статусы, наблюдения и применённые правила. |
| `plots_manifest.json` | Список графиков и состояние их построения. |
| `neoqc_qc_report.html` | Автономный HTML-отчёт для одной стадии QC. |
| `trimming_report.json` | Статистика выполненного тримминга. |
| `neoqc_trimming_report.html` | Автономное сравнение QC до и после тримминга. |

## 8. Интерпретация результатов и QC-статусы

Для технической оценки используются версионируемые правила. Статусы:

| Статус | Значение |
|---|---|
| `PASS` | Рассчитанное наблюдение соответствует выбранным критериям. |
| `WARNING` | Сработал предупреждающий порог. |
| `FAIL` | Сработал порог отказа. |
| `NOT EVALUATED` | Недостаточно данных или отсутствуют необходимые сведения для корректной оценки. |

Статус определяется числовыми наблюдениями и правилами, а не цветом графика. Отсутствие оценки (`NOT EVALUATED`) нельзя считать успешным QC. Технический `FAIL` не означает автоматически, что материал биологически непригоден: результат следует интерпретировать с учётом типа библиотеки и дальнейшего анализа.

HTML-отчёт предоставляет светлую/тёмную тему, переключение EN/RU и два режима порядка разделов: «Приоритет» (сначала проблемные) и «По порядку». Состояние построения графика отделено от статуса QC.

Подробнее:

- [`QC_METRICS.md`](QC_METRICS.md) — описание метрик;
- [`qc-status-engine.md`](qc-status-engine.md) — правила технической оценки;
- [`html-report.md`](html-report.md) — структура и интерфейс HTML-отчёта;
- [`plots.md`](plots.md) — формат графиков и манифеста;
- [`FastQ_origin_paired_end_and_plot_legends.md`](FastQ_origin_paired_end_and_plot_legends.md) — интерпретация FASTQ и графиков.

## 9. Перестроение графиков и отчётов

Для обычного QC, если TSV уже рассчитаны:

```bash
python3 scripts/plot_results.py results/sample01 results/sample01/plots
```

Для тримминга скрипт автоматически обрабатывает обе стадии `qc/before` и `qc/after`:

```bash
python3 scripts/plot_results.py \
  results/sample01_trimmed \
  results/sample01_trimmed/plots
```

Пересобрать только обычный HTML-отчёт из уже готовых артефактов:

```bash
python3 scripts/generate_qc_report.py results/sample01
```

Пересобрать только сравнительный отчёт тримминга из готового каталога:

```bash
python3 scripts/generate_trimming_report.py results/sample01_trimmed
```

Для построения графиков требуется Python-окружение с Matplotlib. Для сборки HTML из уже готовых графиков повторный расчёт FASTQ не требуется. Установка зависимостей описана в [`INSTALL.md`](INSTALL.md).

## 10. Повторный запуск и безопасность результатов

NeoQC выполняет расчёт во временном каталоге и публикует результаты после успешной обработки. Это предотвращает смешивание артефактов различных запусков, например переходов:

```text
paired-end → single-end
обычный QC → QC с --trim
QC с адаптерами → --skip-adapters
```

При использовании того же `--out` предыдущий опубликованный набор результатов заменяется новым. Если необходимо сохранить как первоначальный QC, так и отдельный запуск с триммингом, задайте **разные** каталоги результатов (например, `results/sample01_raw` и `results/sample01_trimmed`).

## 11. Дупликация и производительность

NeoQC рассчитывает дупликацию по первым 50 нуклеотидам прочтения и учитывает уникальные ключи на протяжении всего файла. Потребление оперативной памяти зависит от числа уникальных 50-нуклеотидных префиксов.

Обработка использует OpenMP. После обычного выполнения NeoQC выводит общее время обработки (`Total processing time`) автоматически.

**Важно:** в текущем исходном коде отдельная опция `--timing` не реализована: её передача приводит к ошибке `Unknown argument`. Ориентироваться следует на параметры из `./build/neoqc --help`.

Описание алгоритма дупликации: [`sequence-duplication.md`](sequence-duplication.md).

## 12. Типовой рабочий сценарий

### Шаг 1. Первичный QC исходных FASTQ

```bash
./build/neoqc \
  --r1 sample_R1.fastq.gz \
  --r2 sample_R2.fastq.gz \
  --sample-id sample01 \
  --out results/sample01_raw \
  --plot
```

Откройте `results/sample01_raw/neoqc_qc_report.html` и определите, какие операции предварительной обработки необходимы.

### Шаг 2. Тримминг с автоматическим QC до и после

```bash
./build/neoqc \
  --r1 sample_R1.fastq.gz \
  --r2 sample_R2.fastq.gz \
  --sample-id sample01 \
  --out results/sample01_trimmed \
  --trim \
  --cut-tail --quality-threshold 20 \
  --adapter-config config/adapters/neoqc-standard-v1.tsv \
  --min-length 50 \
  --plot
```

При `--trim` NeoQC выполняет QC исходных и обработанных reads **внутри одного запуска**. Отдельно запускать повторный QC обработанных FASTQ для получения сравнительного отчёта не требуется.

### Шаг 3. Сравнение результатов

Откройте `results/sample01_trimmed/neoqc_trimming_report.html` и проверьте изменение доли адаптеров, распределений качества, длин прочтений, числа сохранённых reads и QC-статусов.

### Шаг 4. Передача очищенных FASTQ дальше

При paired-end используются:

```text
results/sample01_trimmed/trimmed/R1.trimmed.fastq.gz
results/sample01_trimmed/trimmed/R2.trimmed.fastq.gz
```

NeoQC не выполняет выравнивание или вызов вариантов: выходные FASTQ передаются соответствующим инструментам следующего этапа.

## 13. Ошибки входных данных и параметров

NeoQC проверяет, среди прочего:

- корректность структуры FASTQ, заголовка `@` и разделителя `+`;
- совпадение длин последовательности и строки качества;
- допустимость символов последовательности и Phred-качества;
- целостность gzip;
- согласованность paired-end reads;
- существование входных файлов;
- допустимость параметров тримминга и их сочетаний;
- отсутствие входных FASTQ внутри каталога вывода при `--trim`.

Если входные данные некорректны, результаты нельзя интерпретировать как успешно прошедшие QC. При использовании `--plot` NeoQC заранее проверяет доступность необходимых Python-зависимостей.

## 14. Границы возможностей NeoQC

NeoQC выполняет **QC, опциональный тримминг и фильтрацию FASTQ**. Он не является полным NGS-пайплайном и не выполняет:

- выравнивание прочтений на референсный геном (`alignment`);
- поиск генетических вариантов (`variant calling`);
- количественную оценку экспрессии генов и транскриптов (`expression quantification`);
- определение HLA-генотипа (`HLA typing`);
- предсказание неоэпитопов (`neoepitope prediction`).

Планы CUDA-ускорения не следует путать с текущим вычислительным путём: в этой версии вычислительное ядро использует CPU и OpenMP.

```bash
./build/neoqc --help

```

Для отдельных проверок новых компонентов доступны тесты тримминга, пайплайна и сравнительного отчёта из CTest. Актуальные зависимости и сборка описаны в [`INSTALL.md`](INSTALL.md).
